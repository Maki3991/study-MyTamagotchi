# React 页面切换与组件数据流｜学习计划

## 学习目标

用这个项目建立“项目架构阅读能力”，服务于 AI 协作开发。

最终希望你在不亲自编写代码的情况下，也能用自己的话回答：

- 这个项目由哪些部分组成，每个部分负责什么？
- 一个用户动作从哪个前端文件开始？
- 它是否请求了后端？
- 后端修改了什么数据，数据保存在哪里？
- AI 修改了哪些文件，我应该怎样验证修改结果？

React 页面切换仍然是第一个案例，但它只是为了帮助你看懂“用户动作 → 程序处理 → 页面结果”这条链。

## 已知基础与本课边界

已经确认：

- 你能运行这个 mobile 前端，并已经大致理解 `backendApi.ts` 是对后端请求的封装。
- 你的目标是理解项目的文件职责、组件关系和数据流，而不是把每一行代码背下来。

当前不作为主线：

- React 的完整语法；
- TypeScript 类型写法；
- Hook 的实现细节；
- 独立从零编写组件；
- 为了语法本身而拆解单行代码。

这些内容只有在解释一条真实功能链时遇到阻碍，才顺带说明。

## 学习路径

1. 建立项目地图：mobile、backend、SQLite、contracts、bigscreen、hardware。
2. 区分两类动作：只改变页面显示的动作，以及会修改后端数据的动作。
3. 追踪一条真实功能链：Agent 去广场或回到自己的世界。
4. 为这条功能链涉及的文件各写一句职责。
5. 学会用动作、数据、结果和验证方式参与 AI 的修改决策。

## 课程长度说明

本计划没有预先规定固定的总讲数。原本规划的是 5 个阶段，讲数根据真实项目中的理解障碍和你的反馈动态调整：

1. 建立项目地图；
2. 区分页面显示与后端数据；
3. 追踪 Agent 派遣与召回；
4. 认识功能链涉及的文件职责；
5. 学会验证 AI 修改后的结果。

目前已经完成前 5 个阶段的基础框架，后续进入“用真实接口补齐理解”的收尾阶段。第 15 讲已经完成 Agent 列表读取，第 16 讲正在整理功能—函数—文件地图。按当前路线，预计还剩 2—3 讲：Agent 详情、派遣后的刷新，以及最后一次总复盘；完成后再决定是否继续深入其他功能。
