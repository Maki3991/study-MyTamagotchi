# 16｜功能地图：同一个功能里的函数和文件分别负责什么

## 这一讲要解决的问题

你现在已经能理解一条请求的大致逻辑，但看到具体代码时，仍然可能混淆：

- 这个功能到底从哪个文件开始？
- 这个函数是负责页面点击、发送请求，还是修改数据库？
- 名字相似的几个函数是不是同一个函数？

这一讲先不增加新的 React 知识，只建立一张当前项目的“功能—函数—文件”地图。

## 先记住 6 个核心位置

| 位置                                     | 主要职责                                  | 你在这里寻找什么                               |
| ---------------------------------------- | ----------------------------------------- | ---------------------------------------------- |
| `frontends/mobile/src/app/App.tsx`       | 组织页面、保存前端状态、响应用户点击      | 页面组件、按钮事件、页面之间的数据传递         |
| `frontends/mobile/src/app/backendApi.ts` | 集中定义前端可以调用的后端请求            | `agents()`、`agent()`、`dispatch()` 等请求函数 |
| `backend/app/main.py`                    | 接收 API 请求、执行后端业务规则、返回结果 | `@app.get`、`@app.post`、查询和修改逻辑        |
| `backend/app/db.py`                      | 连接 SQLite，并提供数据库 Session         | 数据库文件路径、数据库访问通道                 |
| `backend/app/models.py`                  | 描述数据库表和字段                        | `Agent` 有哪些字段、字段含义是什么             |
| `backend/tamagotchi.db`                  | 保存实际数据                              | 某个 Agent 当前真实的名字、位置、心情等        |

可以先把它们理解成 6 个不同层次。一个功能可能经过其中多个位置，但每个位置回答的问题不同。

## 最容易混淆的一组函数

“把 Agent 派到 Plaza”这个功能里，至少有下面几个函数：

```text
用户点击按钮
  ↓
App.tsx 的 toggleDispatch
  ↓
backendApi.ts 的 dispatch
  ↓
main.py 的 dispatch_agent
  ↓
db.py 提供 Session，修改 Agent 记录并提交
  ↓
App.tsx 更新详情和页面
```

它们名字和功能有关，但它们不是同一个函数。

### 1. `toggleDispatch`：负责响应页面按钮

位置：

`frontends/mobile/src/app/App.tsx:1663-1671`

它属于 `AgentProfileSheet`。用户点击“派遣”或“召回”按钮后，首先运行的是它。

它负责判断当前 Agent 是否在 Plaza，然后决定目标是：

```text
plaza
```

或者：

```text
home
```

它随后调用 `backendApi.dispatch(...)`，等待后端结果，再更新详情和通知外层页面刷新。

所以它属于：

```text
前端页面交互层
```

### 2. `backendApi.dispatch`：负责描述请求

位置：

`frontends/mobile/src/app/backendApi.ts:152-155`

它把前端的业务参数整理成：

```text
POST /api/agents/{agent_id}/dispatch
请求数据：{ location: ... }
```

它不修改 SQLite，也不决定 Agent 最终能否被派遣。它负责把请求发给后端。

所以它属于：

```text
前端请求封装层
```

### 3. `dispatch_agent`：负责后端业务处理

位置：

`backend/app/main.py:240-245` 附近

这里的函数接收 Agent 编号、目标位置和数据库 Session，然后执行后端规则，例如：

- 找不到 Agent 时返回错误；
- 检查目标位置是否有效；
- 派往 Plaza 时记录原来的世界；
- 修改 `agent.location`；
- 提交数据库变化；
- 返回修改后的 Agent。

所以它属于：

```text
后端业务规则层
```

### 这三个函数的对应关系

| 函数                  | 文件            | 负责回答的问题                   |
| --------------------- | --------------- | -------------------------------- |
| `toggleDispatch`      | `App.tsx`       | 用户点击后，前端要做什么？       |
| `backendApi.dispatch` | `backendApi.ts` | 请求应该发到哪里、使用什么方法？ |
| `dispatch_agent`      | `main.py`       | 后端怎样检查并修改数据？         |

以后看到名字相似的函数，先看它所在的文件，再判断它属于哪一层。

## 四条最重要的功能对照

### A. 打开 Agents 页面：读取全部 Agent

| 环节               | 位置                                           |
| ------------------ | ---------------------------------------------- |
| 页面进入后发起读取 | `App.tsx:5498-5511` 的 `AgentsDirectoryScreen` |
| 前端请求函数       | `backendApi.ts:129-130` 的 `agents()`          |
| 网络请求           | `GET /api/agents`                              |
| 后端接口           | `main.py:193-199` 的 `list_agents`             |
| 数据来源           | `Agent` 表，实际文件是 `tamagotchi.db`         |
| 页面保存结果       | `AgentsDirectoryScreen` 内的 `agents` 状态     |

这一条链回答：“Agents 页面上的列表从哪里来？”

### B. Scene 或 Inventory：读取我的 Agent

| 环节         | 位置                                            |
| ------------ | ----------------------------------------------- |
| 刷新函数     | `App.tsx:6648-6655` 的 `refreshMyAgents`        |
| 前端请求函数 | `backendApi.ts:129-130` 的 `agents(ME_USER_ID)` |
| 网络请求     | `GET /api/agents?owner_id=1`                    |
| 后端筛选     | `main.py:193-199` 的 `list_agents`              |
| 页面使用结果 | `dbMyAgents` 传给 Scene、Inventory 等组件       |

这一条链和 A 使用同一个后端接口，区别在于传入了 `owner_id=1` 这个筛选条件。

### C. 点击某个 Agent：读取详情

| 环节         | 位置                                            |
| ------------ | ----------------------------------------------- |
| 详情卡片     | `App.tsx:1623` 的 `AgentProfileSheet`           |
| 详情请求     | `App.tsx:1639` 调用 `backendApi.agent(agentId)` |
| 前端请求函数 | `backendApi.ts:131` 的 `agent(id)`              |
| 网络请求     | `GET /api/agents/{id}`                          |
| 后端接口     | `main.py:202-212` 的 `get_agent`                |
| 额外内容     | 同时读取 memories 和 skills                     |
| 页面保存结果 | `AgentProfileSheet` 内的 `detail` 状态          |

列表接口主要返回多只 Agent 的基础资料；详情接口返回一只 Agent 的更多信息。

### D. 派遣或召回 Agent

| 环节             | 位置                                                  |
| ---------------- | ----------------------------------------------------- |
| 用户点击后的函数 | `App.tsx:1664` 的 `toggleDispatch`                    |
| 请求封装         | `backendApi.ts:152-155` 的 `dispatch`                 |
| 网络请求         | `POST /api/agents/{id}/dispatch`                      |
| 后端处理         | `main.py:244-245` 附近的 `dispatch_agent`             |
| 主要字段         | `Agent.location` 和 `profile` 中的 `home_world`       |
| 页面更新         | `App.tsx:1669-1670` 更新详情并触发 `onChanged`        |
| 世界页面刷新     | `App.tsx:6886-6893` 将 `refreshMyAgents` 传给世界页面 |

这条链回答：“按钮点击以后，位置为什么会真正改变？”

## 你以后应该怎样找一个陌生功能

遇到一个不熟悉的功能时，按下面顺序查：

### 第一步：从页面动作找入口

先找用户看得到的内容：按钮文字、页面标题、错误文字、弹窗名称。

例如你要研究“派遣”，可以先在 `App.tsx` 搜索：

```text
toggleDispatch
```

或者搜索：

```text
派去广场
```

找到的第一个函数，通常是前端页面入口。

### 第二步：看它调用了哪个 `backendApi` 函数

从 `toggleDispatch` 往下看，找到：

```text
backendApi.dispatch(...)
```

然后跳到 `backendApi.ts` 搜索 `dispatch:`。这里能看到请求方法和请求路径。

### 第三步：沿着请求路径找 `main.py`

看到：

```text
/agents/{id}/dispatch
```

就去 `main.py` 搜索包含 `dispatch` 的接口。重点找：

```text
@app.post("/api/agents/{agent_id}/dispatch")
```

这就是后端真正接收请求的位置。

### 第四步：看后端修改了哪个字段

在 `dispatch_agent` 里面找到被修改的字段，然后去 `models.py` 看这个字段属于哪张表。

本功能中最重要的是：

```text
Agent.location
```

所以你再去 `models.py:21-31` 查看 `Agent` 的字段定义，并在 SQLite 中查看实际值。

### 第五步：回到页面看结果怎样重新显示

最后查看后端返回结果之后，前端更新了哪个状态、通过哪个 Props 传给页面。

本功能中可以继续看：

```text
setDetail(...)
onChanged?.()
refreshMyAgents
myAgents={dbMyAgents}
```

这一段负责让“数据库已经改变”变成“页面显示改变”。

## 一个可以直接交给 AI 的提问格式

以后让 AI 分析某个项目功能时，你可以这样问：

```text
请沿着“Agent 派往 Plaza”这条功能链分析，不要逐行解释语法。
请列出：
1. 用户点击后首先进入哪个文件、哪个函数；
2. 它调用了哪个 backendApi 函数；
3. backendApi 发往哪个 HTTP 接口；
4. 后端 main.py 的哪个函数接收；
5. 后端修改了哪个数据库字段；
6. 前端最后通过哪个状态或 Props 显示结果。
每一步给出文件路径和行号，并区分页面交互、请求封装、后端规则和数据库职责。
```

这类问题比“请解释这个项目”更容易得到适合你的答案，因为它规定了追踪范围和输出格式。

## 小结

- 一个产品功能通常会经过多个文件和多个函数。
- 同一个功能里的函数名字可能相似，但它们属于不同层。
- `App.tsx` 负责页面动作和页面状态，`backendApi.ts` 负责请求，`main.py` 负责后端规则，`db.py` 和 `models.py` 负责数据库访问与结构，SQLite 保存实际值。
- 找功能时可以沿着“页面入口 → backendApi → main.py 接口 → 数据库字段 → 页面刷新”这条路径走。
- 你的当前目标不是记住所有函数，而是能够在需要时把一条功能链重新定位出来。
