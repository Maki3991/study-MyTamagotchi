# 03｜`homeView`、State 和 `renderSection()` 到底是什么关系？

## 这一篇要解决的问题

你已经理解了 `homeView` 的核心作用：它保存一个值，条件判断根据这个值选择不同页面。本篇只补上两个连接点：React 的 State 如何保存这个值，以及 `renderSection()` 如何把这个值交给页面选择逻辑。

本篇基于你刚才的反馈生成：你不准备通过写代码学习，所以我们只读项目中的几行代码，理解它们各自负责什么。

## 1. 先确认：你对 `homeView` 的理解基本正确

你的理解可以整理成这样：

```text
homeView 当前是 "plaza"
    ↓
条件判断发现 homeView === "plaza"
    ↓
选择 PlazaScreen
    ↓
网页显示 Public Plaza
```

这里有一个小修正：`homeView` 在这个项目里不能随意写成任何文字。项目在 `App.tsx:5200` 规定了它允许的 4 个值：

```text
"scene" | "civilization" | "plaza" | "chainPlaza"
```

所以它是一个可以改变的变量，但项目提前限定了它可以使用的值。

## 2. `useState` 只解决一件事：让 React 记住这个值

打开 `App.tsx:6625`，你会看到：

```tsx
const [homeView, setHomeView] = useState<HomeView>("scene");
```

先不研究这行的语法，只把它拆成 3 个信息：

| 代码部分                      | 当前项目中的意思                                             |
| ----------------------------- | ------------------------------------------------------------ |
| `homeView`                    | 当前保存的值，初始是 `"scene"`                               |
| `setHomeView`                 | 修改 `homeView` 的函数                                       |
| `useState<HomeView>("scene")` | 告诉 React：请保存一个 `HomeView` 类型的值，起始值是 `scene` |

因此，`useState` 在本课只需要理解为：React 提供的一个函数，用来保存会影响页面的值，并提供一个修改它的函数。

## 3. 为什么不能只用普通变量？

普通 JavaScript 变量可以这样写：

```text
homeView = "scene"
homeView = "plaza"
```

变量的值确实改变了，但 React 未必知道网页需要重新计算。

这个项目使用 `setHomeView` 修改值。调用它时，React 会做两件事：

1. 保存新的值，例如 `"plaza"`；
2. 重新计算受影响的界面。

所以 State 和普通变量的关键差别是：

```text
普通变量：值可以改变
React State：值可以改变，并且改变后会通知 React 更新界面
```

你现在不用学习所有 `use...` Hook。`useState` 先单独理解到这里即可。

## 4. `setHomeView` 在这个项目里从哪里被调用？

`HomeTopTabs` 里的 Plaza 按钮位于 `App.tsx:6568`：

```tsx
onClick={() => onViewChange("plaza")}
```

这一行使用了一个名字叫 `onViewChange` 的函数。App 在 `App.tsx:6861` 把自己的 `setHomeView` 交给了它：

```tsx
onViewChange={setHomeView}
```

把两行连起来读：

```text
点击 Plaza
→ HomeTopTabs 调用 onViewChange("plaza")
→ 实际上就是调用 App 的 setHomeView("plaza")
→ homeView 变成 "plaza"
```

这里先只记住调用关系，不展开讲 Props。

## 5. `renderSection()` 是什么？

`renderSection` 不是 React 规定的特殊词，也不是浏览器自带的功能。它是项目作者自己取的一个普通函数名，定义在 `App.tsx:6803`。

这个函数做的事情是：读取当前的几个值，然后返回一组“应该显示哪些页面组件”的界面结构。它在 `App.tsx:7011` 被调用。

在 `renderSection()` 内部，`App.tsx:6870` 有这一段判断：

```tsx
homeView === "plaza" && <PlazaScreen />;
```

只按意思阅读这一行：

```text
如果 homeView 等于 plaza，就把 PlazaScreen 放进当前界面。
```

所以，`renderSection()` 的作用可以准确说成：

```text
读取页面相关的值
→ 执行条件判断
→ 选择并返回对应的页面组件
```

它负责“选择页面组件”。真正把组件变成浏览器画面的工作由 React 完成。

## 6. 把完整过程连接起来

现在把 `useState`、`setHomeView`、`renderSection()` 放到一起：

```text
初始状态：homeView = "scene"
        ↓
你点击 Plaza
        ↓
调用 setHomeView("plaza")
        ↓
React 保存新值，并重新计算 App 的界面
        ↓
renderSection() 读取到 homeView = "plaza"
        ↓
选择 PlazaScreen
        ↓
React 更新浏览器画面
```

这就是这一条页面切换的完整机制。

## 7. 你可以不写代码，但需要读少量代码

你完全可以把代码实现交给 AI，也不需要练习从零写 React 页面。学习项目架构时，仍然要看少量关键代码，因为文件中的代码才是这个项目实际采用的连接方式。

你需要掌握的是“看到一小段代码后，知道它在流程中的位置”：

- 这一行保存当前值；
- 这一行修改当前值；
- 这一段根据当前值选择页面；
- 这一处把结果交给 React 显示。

你暂时不用掌握：

- 如何自己写 `useState`；
- JSX 的全部语法；
- Hook 的完整体系；
- 如何从零实现 `PlazaScreen`。

## 小结

- `homeView` 保存当前栏目值。
- `setHomeView` 修改这个值，并让 React 重新计算界面。
- `renderSection()` 是项目作者写的普通函数，负责根据值选择页面组件。
- React 负责把被选中的组件显示到浏览器里。
- 你可以不写代码学习，但需要阅读少量关键代码来确认真实数据流。
