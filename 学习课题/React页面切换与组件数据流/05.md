# 05｜为什么把 setHomeView 叫作 onViewChange？

## 这一篇要解决的问题

你已经能够复述点击 Plaza 的完整调用链。现在只解释一个设计问题：App 为什么写成 onViewChange={setHomeView}，而不直接把 setHomeView 这个名字交给 HomeTopTabs。

## 1. 先确认你上一轮的理解

你的理解基本正确：

    用户点击 Plaza
    → HomeTopTabs 调用 onViewChange("plaza")
    → onViewChange 实际指向 setHomeView
    → setHomeView("plaza")
    → homeView 更新
    → renderSection() 选择 PlazaScreen

这一轮只需要修正一个词：当前代码里，onViewChange 不是一个新建的包装函数。它只是接收到了 setHomeView 这个函数。

## 2. 当前写法没有创建新函数

App 中的写法是：

    <HomeTopTabs onViewChange={setHomeView} />

可以先把它理解成下面这个数据关系：

    {
      onViewChange: setHomeView
    }

左边是交给 HomeTopTabs 使用的名称，右边是实际传入的函数。

所以：

    onViewChange === setHomeView

这里的意思不是它们的变量名相同，而是它们指向同一个函数。

HomeTopTabs 内部使用 onViewChange 这个名称，是因为它拿到的是一个名为 onViewChange 的输入。

## 3. 为什么使用 onViewChange 这个名字？

因为 HomeTopTabs 只需要知道一件事：

    当用户选择了一个新的栏目，请调用这个函数，并把新的栏目值传出去。

它不需要知道外部具体使用了哪个 State，也不需要知道这个函数内部叫 setHomeView。

因此在 HomeTopTabs 看来：

    onViewChange = “栏目发生变化时，我要调用的函数”

在 App 看来：

    setHomeView = “修改 homeView 的函数”

同一个函数，在不同组件中的名字表达了不同的职责。

## 4. 直接把 setHomeView 传进去也可以吗？

技术上可以。另一种写法可以是：

    <HomeTopTabs setHomeView={setHomeView} />

然后 HomeTopTabs 内部写：

    function HomeTopTabs({ setHomeView }) {
      // 点击 Plaza 时调用 setHomeView("plaza")
    }

这也可能正常运行。

但这样一来，HomeTopTabs 就知道了父组件内部使用了一个叫 setHomeView 的 State 修改函数。这个组件和 App 的具体实现绑得更紧。

当前写法把两层职责分开：

    App：决定用什么函数修改自己的 State
    HomeTopTabs：只负责在用户操作发生时通知外部

这让 HomeTopTabs 更容易被其他页面复用。未来如果 App 想在切换前检查权限、记录日志，或者同时修改两个值，只需要换传进去的函数，HomeTopTabs 的点击代码仍然可以保持不变。

## 5. 什么时候才算真的创建了包装函数？

下面这种写法才是新建了一个箭头函数：

    <HomeTopTabs
      onViewChange={(view) => {
        console.log(view);
        setHomeView(view);
      }}
    />

这里存在两个函数：

    外层新建的箭头函数
    → 里面调用 setHomeView

外层函数可以在调用 setHomeView 之前或之后增加其他动作。

当前项目的写法：

    onViewChange={setHomeView}

只有一个函数，直接把它传过去，没有额外包装。

可以这样区分：

| 写法                                       | 是否新建函数 | 含义                                 |
| ------------------------------------------ | -----------: | ------------------------------------ |
| onViewChange={setHomeView}                 |           否 | 直接传递 setHomeView                 |
| onViewChange={(view) => setHomeView(view)} |           是 | 新建函数，函数内部再调用 setHomeView |

## 6. onViewChange 为什么叫 on 开头？

onViewChange 是项目作者选择的命名方式。React 没有规定必须叫这个名字。

通常：

    onClick       表示点击发生时执行的函数
    onChange      表示值发生变化时执行的函数
    onViewChange  表示页面栏目发生变化时执行的函数

这个 on 开头的名称告诉阅读者：它通常是一个“发生某个操作后，通知外部”的函数。

## 7. 结合当前源码定位

只看这 3 个位置：

- App.tsx:6493：HomeTopTabs 声明自己接收名为 onViewChange 的函数；
- App.tsx:6568：点击 Plaza 时调用 onViewChange("plaza")；
- App.tsx:6861：App 把 setHomeView 作为这个输入传进去。

把它们按组件边界读：

    App 传入：onViewChange = setHomeView
    HomeTopTabs 接收：onViewChange
    HomeTopTabs 调用：onViewChange("plaza")
    实际效果：setHomeView("plaza")

## 小结

- onViewChange={setHomeView} 没有创建新的包装函数。
- 它把 setHomeView 这个函数传给 HomeTopTabs，并在子组件中使用 onViewChange 这个名称。
- 这个名称表达的是“栏目变化时通知外部”，不暴露 App 内部 State 的实现细节。
- 如果使用箭头函数包住 setHomeView，才会产生额外的包装函数。
- 左侧名称是组件约定的输入名，右侧是实际传入的值。
