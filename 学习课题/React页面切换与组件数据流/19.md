# 19｜派遣成功后为什么还要刷新：详情卡片和世界列表

## 这一讲只看一个问题

你之前遇到过这种现象：

~~~text
点击召回
→ 后端已经成功修改位置
→ 详情卡片显示了新位置
→ 世界画面里的 Agent 还停留在旧位置
~~~

这一讲只解释：为什么同一次操作需要更新两处前端数据。

## 第一步：后端先修改真正的数据

用户点击派遣或召回按钮后，前端会调用：

~~~text
App.tsx:1664
toggleDispatch
~~~

它通过：

~~~text
backendApi.dispatch(...)
~~~

发送请求：

~~~text
POST /api/agents/{agent_id}/dispatch
~~~

后端位置：

~~~text
backend/app/main.py:244-263
dispatch_agent
~~~

后端会：

1. 找到这只 Agent；
2. 判断目标位置；
3. 修改 agent.location；
4. 保存数据库；
5. 返回修改后的 Agent。

最重要的是：

~~~text
agent.location = target
session.commit()
~~~

到这里，SQLite 中的真实数据已经改变。

## 第二步：详情卡片先更新自己

后端返回修改后的 Agent 后，toggleDispatch 里有一行：

~~~text
setDetail(current => ...)
~~~

位置：

~~~text
App.tsx:1668-1669
~~~

它做的事情是：

~~~text
把详情卡片正在显示的 Agent 位置改成后端返回的新位置。
~~~

所以详情卡片会立即更新。例如：

~~~text
原来：location = plaza
点击召回
返回：location = vitality-gym-town
详情卡片显示：vitality-gym-town
~~~

这只改变了 AgentProfileSheet 内部的 detail。

## 第三步：为什么世界画面还可能是旧的

世界画面使用的 Agent 列表来自 App 中的：

~~~text
dbMyAgents
~~~

这个列表通过：

~~~text
refreshMyAgents
→ backendApi.agents(ME_USER_ID)
→ setDbMyAgents
~~~

位置：

~~~text
App.tsx:6648-6649
~~~

世界页面接收的是这份列表：

~~~text
App.tsx:6886-6892
myAgents={dbMyAgents}
~~~

因此，页面里同时存在两份前端数据：

~~~text
detail
→ 详情卡片当前显示的数据

dbMyAgents
→ 世界页面使用的 Agent 列表
~~~

如果只更新 detail，dbMyAgents 仍然可能保留旧的 location。世界页面继续使用旧列表，就会继续把 Agent 显示在旧位置。

## 第四步：onChanged 的作用

详情卡片完成数据库操作后，会调用：

~~~text
onChanged?.()
~~~

位置：

~~~text
App.tsx:1670
~~~

这里的 onChanged 可以理解成：

~~~text
告诉外层页面：数据已经改变，请重新读取列表。
~~~

它不是按钮，也不是 API。它是一个由外层页面传进来的通知函数。

在世界页面中，这个通知最终对应到 App 里的：

~~~text
refreshMyAgents
~~~

所以调用关系是：

~~~text
详情卡片里的 onChanged
→ App 里的 refreshMyAgents
→ backendApi.agents(ME_USER_ID)
→ 后端重新返回最新 Agent 列表
→ setDbMyAgents
→ 世界页面收到新 myAgents
→ 世界中的 Agent 重新显示
~~~

## 这次操作的完整链路

~~~text
用户点击召回
  ↓
toggleDispatch
  ↓
backendApi.dispatch
  ↓
POST /api/agents/3/dispatch
  ↓
main.py 的 dispatch_agent
  ↓
修改 agent.location 并 session.commit()
  ↓
返回更新后的 Agent
  ↓
setDetail：更新详情卡片
  ↓
onChanged：通知外层数据已改变
  ↓
refreshMyAgents
  ↓
GET /api/agents?owner_id=1
  ↓
setDbMyAgents
  ↓
世界页面使用最新 Agent 列表
~~~

## 只更新一处会怎样

### 只更新数据库，不更新前端

~~~text
数据库是新位置
页面仍显示旧位置
~~~

### 只更新 detail

~~~text
详情卡片显示新位置
世界地图或世界预览仍可能显示旧位置
~~~

### 更新 detail，并重新读取 dbMyAgents

~~~text
详情卡片和世界页面都使用最新位置
~~~

这就是“请求成功以后还要刷新列表”的原因。

## 如何用 Network 验证

点击一次召回，然后观察请求顺序：

~~~text
1. POST /api/agents/3/dispatch
2. GET /api/agents?owner_id=1
~~~

第一条请求负责修改位置。

第二条请求负责重新读取最新列表。

如果第一条请求成功，第二条请求没有出现，页面外层列表就可能继续使用旧数据。

## 小结

- 数据库里的 location 是真正保存下来的位置。
- detail 是详情卡片自己的前端数据。
- dbMyAgents 是外层世界使用的 Agent 列表。
- setDetail 让详情卡片更新。
- onChanged 通知外层重新读取列表。
- refreshMyAgents 通过 GET 请求取得最新 Agent 列表。
- 页面完全同步需要同时更新详情卡片和外层列表。

这一讲的核心可以压缩成：

~~~text
局部详情更新
≠
整个页面数据更新
~~~
