# 15｜Agent 列表从哪里来：同一个接口如何返回“全部”或“我的”

## 这一讲要解决的问题

你之前已经看过 Agent 被派往 Plaza 的请求，但还有一个更基础的问题：页面刚打开时，Agent 列表里的 `id`、名字、心情和 `location` 到底从哪里来？

这一讲只追踪“读取 Agent 列表”这一件事，并比较两种情况：

- Agents 页面读取全部 Agent；
- Scene、Inventory 等地方读取当前用户自己的 Agent。

重点仍然是文件职责和数据经过哪些位置，不要求记住 React 或 TypeScript 语法。

## 先看完整链路

以“刷新当前用户自己的 Agent 列表”为例：

```text
App.tsx
  ↓ 调用 refreshMyAgents()
backendApi.ts
  ↓ 组成 GET /api/agents?owner_id=1
Python main.py
  ↓ 根据 owner_id 查询 Agent
db.py + tamagotchi.db
  ↓ 读出数据库记录
main.py
  ↓ 把记录整理成 JSON
App.tsx
  ↓ 保存到前端状态
Scene / Inventory
  ↓ 根据这些数据显示 Agent
```

这里没有修改数据。它是一条“读取链”：数据库里的内容经过后端返回给前端，前端再把结果显示出来。

## 第一个入口：App.tsx 请求“我的 Agent”

打开：

`frontends/mobile/src/app/App.tsx:6648-6655`

这里有一个叫 `refreshMyAgents` 的函数。它调用：

```text
backendApi.agents(ME_USER_ID)
```

当前项目里的 `ME_USER_ID` 是 `1`。因此，这个调用表达的是：

```text
请把 owner_id 等于 1 的 Agent 给我。
```

请求完成后，返回的列表会被放进 `dbMyAgents`。这个变量随后会传给 Scene、Inventory 等页面，页面据此显示 Agent。

所以，`App.tsx` 在这里负责两件事：

1. 决定什么时候重新读取“我的 Agent”；
2. 保存读取结果，交给页面显示。

它没有直接打开 SQLite 文件，也没有自己判断哪些 Agent 属于用户 1。

## 第二个入口：Agents 页面请求“全部 Agent”

打开：

`frontends/mobile/src/app/App.tsx:5498-5511`

这里的 `AgentsDirectoryScreen` 进入页面后调用：

```text
backendApi.agents()
```

这次没有传入 `ME_USER_ID`，意思是读取全部 Agent。结果被保存到这个页面自己的 `agents` 状态中。

两处都调用了 `backendApi.agents`，但传入的参数不同：

| 调用位置       | 调用方式                        | 想得到什么           |
| -------------- | ------------------------------- | -------------------- |
| `App.tsx:6649` | `backendApi.agents(ME_USER_ID)` | 当前用户自己的 Agent |
| `App.tsx:5507` | `backendApi.agents()`           | 所有 Agent           |

这里体现了一个很重要的阅读方法：看到同一个函数名时，继续看它有没有参数，以及参数改变了什么结果。

## 第三步：backendApi.ts 把调用变成 URL

打开：

`frontends/mobile/src/app/backendApi.ts:6`

这里规定默认后端地址是：

```text
http://127.0.0.1:8000/api
```

再看：

`frontends/mobile/src/app/backendApi.ts:112-121`

`req` 函数负责使用 `fetch` 发请求，并检查后端是否返回成功结果。

再看：

`frontends/mobile/src/app/backendApi.ts:128-131`

`agents` 函数会根据有没有 `ownerId`，组成两种地址：

```text
backendApi.agents()
→ GET http://127.0.0.1:8000/api/agents

backendApi.agents(1)
→ GET http://127.0.0.1:8000/api/agents?owner_id=1
```

这就是“前端函数调用”变成“网络请求地址”的位置。

注意：这两条请求都是 `GET`。它们的目的只是读取数据，所以没有请求体，也不会像派遣 Agent 那样发送 `{ location: "plaza" }`。

## 第四步：main.py 接收并筛选

打开：

`backend/app/main.py:193-199`

这里定义了 `/api/agents` 接口。它有一个可选的 `owner_id` 条件：

```text
GET /api/agents
```

后端查询全部 Agent。

```text
GET /api/agents?owner_id=1
```

后端只保留 `owner_id` 等于 `1` 的 Agent。

因此，`owner_id=1` 不是数据库里新建的一条数据，也不是前端随便写出来的 Agent 内容。它是一个筛选条件，告诉后端“只返回属于这个用户的记录”。

## 第五步：db.py 和 models.py 分别做什么

### db.py：负责连接数据库

打开：

`backend/app/db.py:5-9`

这里把数据库文件定位到：

```text
backend/tamagotchi.db
```

打开 `backend/app/db.py:76-78`，可以看到后端请求会取得一个数据库 Session。你可以把它理解成：这次请求暂时拿到一个可以读取数据库的通道。

### models.py：说明 Agent 记录有哪些字段

打开：

`backend/app/models.py:21-31`

这里描述一条 Agent 记录具有什么字段，例如：

- `id`：Agent 的编号；
- `owner_id`：它属于哪个用户；
- `name`：名字；
- `mood`：保存的心情值；
- `location`：当前所在位置；
- `profile`：身份和记忆等 JSON 内容。

`models.py` 主要说明“记录长什么样”。具体某只 Agent 当前的值，保存在 `tamagotchi.db` 里。

## 第六步：后端把数据库记录整理成 JSON

打开：

`backend/app/main.py:108-120`

这里的 `agent_out` 把后端读到的 Agent 对象整理成前端能接收的 JSON。返回内容里包括：

```text
id
owner_id
name
image
trait
mood
location
profile
```

因此，页面上的 `location` 的来源可以完整地追溯为：

```text
tamagotchi.db 里的 Agent.location
  → main.py 查询到的 Agent 对象
  → agent_out 整理出的 JSON.location
  → 前端保存的 Agent 数据
  → 页面上的位置文字或角色位置
```

这也回答了一个容易混淆的问题：加载 Agent 时，`location` 通常不在前端请求里。它在后端返回的结果里。

## 在浏览器里怎么验证

打开页面的 Network 面板，筛选 `Fetch/XHR`。

### 验证 Agents 页面

1. 点击顶部 `Agents`。
2. 找到 `agents` 请求。
3. 查看请求地址，应该接近：

   ```text
   http://127.0.0.1:8000/api/agents
   ```

4. 查看请求方法，是 `GET`。
5. 打开“响应”，在返回的数组里找 `id`、`name`、`location`。

### 验证“我的 Agent”

1. 进入会刷新自己 Agent 的页面，或刷新页面。
2. 找到地址中带有：

   ```text
   /api/agents?owner_id=1
   ```

3. 对比响应内容和 Agents 页面。

你会看到：请求地址的筛选条件不同，返回列表的范围也不同；每条记录内部的 `id`、`location` 等字段来自后端响应。

## 小结

- `App.tsx` 决定什么时候读取 Agent，并保存读取结果。
- `backendApi.ts` 把 `agents()` 或 `agents(1)` 变成具体的 GET 地址。
- `main.py` 接收请求，并根据 `owner_id` 决定返回全部还是部分 Agent。
- `db.py` 提供数据库访问通道，`models.py` 描述 Agent 记录的字段。
- `tamagotchi.db` 保存实际值，`agent_out` 把它整理成 JSON 返回给前端。
- Agent 的 `location` 来自后端返回结果，不需要由加载列表的前端请求再次发送。
