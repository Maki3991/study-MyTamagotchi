# 17｜点击一张 Agent 卡片：查看这只 Agent 的详情

## 这一讲只看一个功能

本讲只研究这一件事：

```
打开 Agents 页面
→ 点击一张 Agent 卡片
→ 这张卡片展开
→ 显示这只 Agent 的技能和记忆
```

本讲暂时不看 Scene、Plaza、profileAgentId 和 AgentProfileSheet。它们属于其他页面中的另一种详情显示方式，之后再单独学习。

## 第一步：页面先拿到 Agent 列表

页面组件是：

```text
frontends/mobile/src/app/App.tsx:5499
AgentsDirectoryScreen
```

它进入页面后调用：

```text
backendApi.agents()
```

调用位置是 App.tsx:5505-5511。后端会返回一个列表，例如：

```json
[
  { "id": 3, "name": "豆豆" },
  { "id": 4, "name": "雪糕" }
]
```

前端把这个列表保存到 agents 变量里。

这里的 agents 是前端变量，里面装着多只 Agent 的数据。每一条数据都带有自己的 id。

## 第二步：列表变成一张张卡片

位置：

```text
App.tsx:5537
```

代码使用：

```text
agents.map(agent => ...)
```

你可以把它直接理解成：

```text
把 agents 列表里的每一条 Agent 依次拿出来，生成一张卡片。
```

假设当前拿出来的是：

```text
{ id: 3, name: "豆豆" }
```

那么当前这张卡片里的 agent.id 就是 3。

编号不是用户点击后才产生的。编号早已在后端返回的 Agent 数据里，卡片只是使用它。

## 第三步：用户点击卡片后保存编号

位置：

```text
App.tsx:5502
```

页面有一个前端变量：

```text
expandedId
```

它只保存一件事：

```text
当前哪一张卡片被展开了？
```

它刚进入页面时没有值，因为还没有卡片被点击。

卡片的点击位置是 App.tsx:5541-5545。点击“豆豆”这张卡片时：

```text
当前 agent.id = 3
→ setExpandedId(3)
→ expandedId 变成 3
```

所以 expandedId 可以暂时理解成：

```text
被点击的那张卡片的 Agent 编号。
```

它不是数据库表、数据库文件或后端函数。它只是 AgentsDirectoryScreen 运行期间保存的一个前端变量。

它叫 expandedId，是因为这个编号对应的卡片会展开。

## 第四步：根据编号请求详情

当 expandedId 变成 3 后，App.tsx:5513-5520 会调用：

```text
backendApi.agent(expandedId)
```

实际效果是：

```text
backendApi.agent(3)
→ GET /api/agents/3
→ main.py 的 get_agent(3)
```

后端会读取：

```text
id = 3 的 Agent
这只 Agent 的 memories
这只 Agent 的 skills
```

然后把详情返回给前端。

## 第五步：前端收到详情并展开卡片

后端返回的结果会被保存到：

```text
detail
```

detail 也是前端变量，保存当前被点击 Agent 的详细资料。

页面会判断：

```text
expandedId === agent.id
```

对于豆豆这张卡片：

```text
expandedId = 3
agent.id = 3
```

两个值相等，所以这张卡片展开，并显示 Skills 和最近记忆。

## 整条流程

```text
后端返回 Agent 列表
  ↓
agents 保存列表
  ↓
map 为每只 Agent 生成一张卡片
  ↓
用户点击某张卡片
  ↓
从当前卡片的 agent.id 得到编号 3
  ↓
expandedId 保存 3
  ↓
backendApi.agent(3)
  ↓
GET /api/agents/3
  ↓
main.py 的 get_agent 查询详情
  ↓
detail 保存返回结果
  ↓
编号为 3 的卡片展开
```

## 本讲暂时跳过的名字

为了保持主线清楚，本讲暂时跳过：

```text
profileAgentId
AgentProfileSheet
Scene 路径
Plaza 路径
```

它们解决的是另一个界面中的类似动作：点击 Scene 或 Plaza 里的 Agent，然后弹出详情面板。当前不需要把它们和 AgentsDirectoryScreen 混在一起理解。

本讲只需要记住：

```text
AgentsDirectoryScreen
→ expandedId
→ backendApi.agent(expandedId)
→ get_agent
→ 卡片展开
```

## 小结

- AgentsDirectoryScreen 显示多只 Agent 的卡片。
- 每张卡片的数据里本来就有 agent.id。
- 用户点击卡片后，setExpandedId(agent.id) 保存被点击 Agent 的编号。
- expandedId 是前端变量，用来记住哪张卡片要展开。
- 后端根据这个编号读取单个 Agent 的详情、记忆和 Skills。
- detail 保存详情结果，卡片根据它显示更多内容。

本讲实现的功能只有一个：

```text
在 Agents 列表中点击一只 Agent，并查看它的详情。
```
