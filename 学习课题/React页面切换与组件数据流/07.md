你已经指出了前面学习中的核心问题：每一节的局部内容可以看懂，但局部内容和整个项目的关系没有被保留下来。

## 1. 你最终要获得的能力

假设你告诉 AI：

    把“派 Agent 去广场”这个功能改成可以自动派遣。

你不需要自己写代码，但你应该能够参与这些判断：

1. 用户是在手机端的哪个页面触发这个功能？
2. 手机端需要把什么信息交给后端？
3. 后端的哪个接口接收这个动作？
4. 后端修改了哪个数据？
5. 数据保存在哪里？
6. 修改完成后，手机端怎样知道要重新显示？
7. 我应该怎样操作页面、查看日志或查看数据库，确认 AI 的修改真的生效？

这就是本课题的最终方向。

你学习的产出不是“记住 React 的所有写法”，而是一张可以用于和 AI 协作的项目地图，以及几条可以被验证的功能链。

## 2. 当前项目由哪些部分组成？

先把仓库根目录的 README.md 翻译成职责：

| 项目部分              | 在这个项目里负责什么                                  |
| --------------------- | ----------------------------------------------------- |
| frontends/mobile      | 手机端界面。用户点击、查看世界、管理 Agent、进入广场  |
| backend               | 共享后端。接收手机端请求，执行规则，读写数据          |
| backend/tamagotchi.db | SQLite 数据库。保存 Agent、世界位置、技能、记忆等数据 |
| contracts             | 前端和后端之间约定的数据格式                          |
| frontends/bigscreen   | 面向大屏展示的另一套前端                              |
| frontends/hardware    | 面向硬件设备的程序                                    |

先看手机端最主要的一条链：

    你在浏览器中点击
    → frontends/mobile 显示界面并发起动作
    → backend/app 接收请求并处理业务
    → tamagotchi.db 保存需要长期保留的数据
    → backend 把结果返回给手机端
    → frontends/mobile 重新显示结果

这张图就是我们后面所有学习的方向。

## 3. “传入”在这个项目里到底是什么意思？

你问“App 传入什么”，可以先完全脱离语法理解。

App 是当前手机页面的总协调者。它知道现在显示的是 Scene、Agents 还是 Plaza，也知道当前选中了哪个世界。

HomeTopTabs 是页面顶部的导航栏。它只负责显示几个按钮，并把用户的点击告诉 App。

因此，App 显示 HomeTopTabs 时，要把导航栏工作所需要的信息交给它：

| 交给顶部导航栏的内容         | 它为什么需要                   |
| ---------------------------- | ------------------------------ |
| 当前选中的 Scene 子页面      | 顶部导航栏需要知道当前状态     |
| 当前选中的顶部栏目           | 顶部导航栏需要突出显示当前栏目 |
| Scene 发生变化时的通知方式   | 用户点了 Scene 后，要告诉 App  |
| 顶部栏目发生变化时的通知方式 | 用户点了 Plaza 后，要告诉 App  |
| 当前页面的颜色               | 导航栏需要使用对应的视觉颜色   |

这就是“传入”的实际含义：

    App 正在组装手机页面
    → 页面里需要一个顶部导航栏
    → App 把导航栏显示所需的当前信息和操作方式交给它
    → 导航栏根据这些信息显示，并在用户点击后通知 App

这里没有网络请求，也没有数据库。它只是同一个手机端内部的两个组件在配合工作。

所以，HomeTopTabs 的传入数据有一个很具体的功能：

    让一个较小的导航栏，能够显示当前状态，并把用户操作报告给负责整体页面的 App。

## 4. 同一个项目里有两类不同的数据流

这一步很重要。你之前看到的顶部栏目切换，和“把 Agent 派到广场”不是同一种操作。

### A. 顶部栏目切换：只改变手机端当前显示

    点击 Plaza
    → 手机端记录当前栏目是 Plaza
    → 手机端选择显示 Public Plaza

这个动作主要发生在 App.tsx 内部，通常不需要修改数据库。

### B. 派 Agent 去广场：改变项目中的持久数据

    点击派遣
    → 手机端告诉后端“哪个 Agent 去哪里”
    → 后端修改 Agent 的 location
    → SQLite 保存这个位置
    → 手机端重新读取结果
    → Scene 和 Plaza 显示新的位置

这个动作会经过前端、后端和数据库。

今后读代码时，第一件事先判断：

    我现在看的动作，只是在切换界面？
    还是在改变项目里的真实数据？

这个判断比先拆某个函数的语法更重要。

## 5. 用“派 Agent 到广场”看一条完整功能链

这条功能链和你已经实际操作过的页面直接对应。

### 第一步：用户动作

你在 Agent 详情里点击“派往广场”或“收回”。

相关位置：frontends/mobile/src/app/App.tsx，第 1668 行附近。

这里的产品动作是：

    把当前这个 Agent 的位置，在“自己的世界”和“广场”之间切换。

### 第二步：手机端发出请求

手机端要告诉后端两件事：

    哪一个 Agent
    要移动到哪里

相关位置：frontends/mobile/src/app/backendApi.ts，第 152–155 行。

这里的 backendApi.dispatch 可以先理解成：

    手机端向后端提交“移动某个 Agent”的请求。

它本身不负责决定数据库怎么改。它只是把动作和必要信息送到后端。

### 第三步：后端处理规则

后端接收的接口在：

    backend/app/main.py，第 244–264 行

后端会检查：

    这个 Agent 是否存在
    目标位置是不是允许的值
    如果是去广场，是否需要记住它原来的世界

然后更新 Agent 的位置。

### 第四步：数据库保存

Agent 的位置对应数据库中的 location 字段。

后端把新的 location 写入 SQLite。这样即使你刷新页面，程序仍然可以根据数据库里的位置显示 Agent。

数据库连接的基础位置在：

    backend/app/db.py，第 5–10 行

### 第五步：手机端显示结果

后端返回更新后的 Agent 信息，手机端更新自己的列表。

之后：

    Plaza 根据 location 是 plaza 来显示 Agent
    Scene 根据 location 是三个世界之一来显示 Agent

这就解释了为什么“派遣”是一个跨层功能，而顶部栏目切换主要是手机端内部的页面选择。

## 6. 以后每个功能都用这 5 个问题阅读

看到一个功能时，只回答下面 5 个问题：

1. 用户做了什么动作？
2. 哪个前端部分接住了这个动作？
3. 后端有没有收到请求？
4. 哪个数据被读取或修改？
5. 页面最后怎样显示结果？

如果第 3 个问题的答案是“没有”，它可能只是前端内部的显示切换。

如果第 3 个问题的答案是“有”，就继续追踪后端和数据库。

如果 AI 提议修改代码，你也可以用同一组问题检查它的方案：

    它改了哪一层？
    它改变了哪条数据链？
    它准备怎样验证？

## 7. 我们接下来的学习顺序

接下来不按 React 语法顺序学习，按项目运行逻辑学习：

### 第一阶段：项目地图

知道 mobile、backend、database、contracts、bigscreen、hardware 各自负责什么。

### 第二阶段：一条真实功能链

先追踪“Agent 去广场／回到世界”：

    手机端
    → backendApi.dispatch
    → 后端 dispatch 接口
    → Agent.location
    → SQLite
    → 页面重新显示

### 第三阶段：文件职责

为这条功能链涉及的每个文件写一句话：

    它负责接收什么
    它负责处理什么
    它把结果交给谁

### 第四阶段：AI 协作和验收

当 AI 要修改功能时，你能够先判断：

    它应该改哪几个文件
    它有没有漏掉数据库或接口
    我应该怎样操作页面确认结果

React 的具体语法只在这条功能链确实需要解释时出现。我们不会单独为了学习语法而继续拆语法。

## 小结

- 这门学习的主线是项目架构阅读和 AI 协作，不是 React 语法背诵。
- “传入”表示 App 把导航栏显示和工作所需的信息交给 HomeTopTabs。
- 顶部栏目切换主要改变手机端当前显示。
- Agent 派遣会改变后端数据，并保存到 SQLite。
- 阅读任何功能，都先追踪“动作 → 处理 → 数据 → 结果”。
- 下一步会从一条真实的跨层功能链开始。
