# 06｜HomeTopTabs 如何接收传入的内容？

## 这一篇只解决一个问题

上一讲你已经理解了：

    onViewChange={setHomeView}

表示 App 把 setHomeView 这个函数交给 HomeTopTabs 使用。

这一讲只继续往下看：HomeTopTabs 是怎样把这些传入的内容接收到自己内部的。

暂时不学习新的页面，不学习后端，也不学习如何写 React 组件。

## 1. 先看 App 传入了什么

位置：frontends/mobile/src/app/App.tsx，第 6856–6864 行。

    <HomeTopTabs
      scene={homeSub}
      view={homeView}
      onSceneChange={setHomeSub}
      onViewChange={setHomeView}
      accent={homeAccent}
    />

这里 App 传入了 5 个有名字的值：

| 传入名称      | 实际传入的值 | 可以先理解成            |
| ------------- | ------------ | ----------------------- |
| scene         | homeSub      | 当前选中的 Scene 子页面 |
| view          | homeView     | 当前选中的顶部栏目      |
| onSceneChange | setHomeSub   | 修改 Scene 子页面的函数 |
| onViewChange  | setHomeView  | 修改顶部栏目的函数      |
| accent        | homeAccent   | 当前页面使用的强调色    |

例如：

    onViewChange={setHomeView}

左边的 onViewChange 是交给 HomeTopTabs 使用的名称，右边的 setHomeView 是实际传进去的函数。

## 2. 再看 HomeTopTabs 怎样接收

位置：frontends/mobile/src/app/App.tsx，第 6489–6496 行。

    function HomeTopTabs({ scene, view, onSceneChange, onViewChange, accent }: {
      scene: HomeScene;
      view: HomeView;
      onSceneChange: (scene: HomeScene) => void;
      onViewChange: (view: HomeView) => void;
      accent: string;
    }) {

先只看这段代码中最重要的两个部分：

    function HomeTopTabs({ scene, view, onSceneChange, onViewChange, accent })

以及：

    : {
      scene: HomeScene;
      view: HomeView;
      ...
    }

第一部分表示：这个函数接收一组传入的内容，并把里面的字段直接取出来使用。

第二部分表示：作者写出了这组内容应该是什么类型。

所以，这里不是在调用 onViewChange，也不是在修改 homeView。这里是在声明 HomeTopTabs 可以接收什么。

## 3. 花括号里的内容到底做了什么？

这一段：

    function HomeTopTabs({ scene, view, onSceneChange, onViewChange, accent })

可以先按下面的意思理解：

    function HomeTopTabs(props) {
      const scene = props.scene;
      const view = props.view;
      const onSceneChange = props.onSceneChange;
      const onViewChange = props.onViewChange;
      const accent = props.accent;
    }

上面这段不是项目原文，而是为了帮助你翻译语法。

它表达的是同一件事：

    父组件传入一组内容
    → HomeTopTabs 收到这组内容
    → 从这组内容中取出 scene、view、onSceneChange、onViewChange、accent
    → 函数内部可以直接使用这些名称

这种把对象里的字段直接取成变量的写法，通常叫“对象解构”。

现在不需要记住“对象解构”这个术语。你只需要记住它完成了一个动作：

    把传入对象里的字段取出来，变成函数内部可以直接使用的名称。

## 4. 冒号后面的代码是什么？

例如这一行：

    onViewChange: (view: HomeView) => void;

它不是一个正在执行的函数，而是在描述 onViewChange 这个输入应该是什么样的函数。

可以拆成三部分：

    onViewChange

表示输入的名称。

    (view: HomeView)

表示这个函数接收一个叫 view 的内容，而且这个内容应该属于 HomeView 类型。

HomeView 在 App.tsx 第 5200 行附近定义，当前允许的值包括：

    scene
    civilization
    plaza
    chainPlaza

    => void

表示这个函数不需要返回一个有用的结果。

因此整行可以先翻译成：

    onViewChange 是一个函数；
    它接收一个 HomeView 类型的栏目值；
    调用结束后不返回需要继续使用的结果。

这里的类型描述不会自己改变页面，也不会自己调用 setHomeView。

真正调用它的位置仍然是 App.tsx 第 6568 行：

    onClick={() => onViewChange("plaza")}

## 5. 传入名称、接收名称和实际值

把父组件和子组件放在一起看：

| App 传入                   | HomeTopTabs 接收 | 实际对应的东西       |
| -------------------------- | ---------------- | -------------------- |
| scene={homeSub}            | scene            | homeSub 当前的值     |
| view={homeView}            | view             | homeView 当前的值    |
| onSceneChange={setHomeSub} | onSceneChange    | setHomeSub 这个函数  |
| onViewChange={setHomeView} | onViewChange     | setHomeView 这个函数 |
| accent={homeAccent}        | accent           | homeAccent 当前的值  |

其中两边名称相同，是因为作者希望接收后可以直接使用同一个名称。

最重要的一行仍然是：

    onViewChange={setHomeView}

它在 App 中传出的是 setHomeView；进入 HomeTopTabs 后，接收时使用的名称是 onViewChange；点击 Plaza 时，HomeTopTabs 调用 onViewChange("plaza")，实际效果仍然是 setHomeView("plaza")。

## 6. 只区分这三种花括号

在这一小段代码里，你会看到几种花括号。它们位置不同，作用也不同。

### 第一种：JSX 中的花括号

    onViewChange={setHomeView}

意思是：把已经存在的 setHomeView 这个值放进组件输入里。

### 第二种：函数参数中的花括号

    function HomeTopTabs({ scene, view, onViewChange })

意思是：从函数收到的那组内容中，取出这些字段，作为函数内部可以使用的名称。

### 第三种：类型描述中的花括号

    : {
      scene: HomeScene;
      view: HomeView;
      onViewChange: (view: HomeView) => void;
    }

意思是：说明这组传入内容应该有哪些字段，以及每个字段是什么类型。

你现在只需要把它们区分为：

    JSX 花括号：放入一个值
    参数花括号：取出传入对象里的字段
    类型花括号：描述对象应该长什么样

## 7. 回到完整调用链

只追踪这 3 个位置：

    App.tsx:6861
    → App.tsx:6489
    → App.tsx:6568

对应的过程是：

    App 在第 6861 行把 setHomeView 传进去
    → HomeTopTabs 在第 6489 行把它接收为 onViewChange
    → 用户点击 Plaza
    → 第 6568 行调用 onViewChange("plaza")
    → 实际调用 setHomeView("plaza")

这就是“父组件传入一个函数，子组件接收并调用这个函数”的完整过程。

## 小结

- App 在第 6856–6864 行给 HomeTopTabs 传入 5 个有名字的值。
- HomeTopTabs 在第 6489–6496 行接收这一组值。
- 参数花括号负责把传入对象中的字段取出来。
- 冒号后面的花括号不是执行代码，而是在描述这些输入的类型。
- onViewChange 最终仍然对应 App 中的 setHomeView。
- 这一次的重点不是记住术语，而是看懂“传入 → 接收 → 使用”。
