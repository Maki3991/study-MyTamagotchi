# 01｜React 页面到底是怎么切换的？

## 这篇要解决的问题

你现在不需要学习“怎么写一个 React 页面”，只需要看懂：当你在网页上点击一个按钮时，项目内部是谁接收了点击、谁记录了新的页面状态，以及谁最终把新页面显示出来。

本课只追踪这一条链：

`main.tsx → App → State → HomeTopTabs → navigate() → renderSection() → Screen`

## 1. `main.tsx`：应用的启动入口

打开 `frontends/mobile/src/main.tsx`，最开始的几行可以理解成“把 React 应用装进浏览器里的根节点”。它做的核心事情是：

1. 找到 HTML 中名为 `root` 的容器；
2. 把 `<App />` 放进去；
3. 让 `App` 成为整个界面的最外层组件。

所以，当前项目不是从某个 `pages/Home.tsx` 开始，而是从 `main.tsx` 启动，再进入 `App.tsx`。

后面与启动画面、PWA 注册有关的代码，这一课先跳过。

## 2. `App`：保存“现在正在看什么”

`App.tsx` 里的 `App` 是总控组件。它有许多 State，但第一课只看四个：

- `bottomTab`：底部是在 Home、Capture 还是 Inventory；
- `homeView`：Home 内部是在 Scene、Agents、Plaza 还是链上广场；
- `homeSub`：Scene 内部具体选中了哪个世界，例如 `worldDock`、Vitality Gym、Learning Commons 或 Maker Harbor；
- `detailScreen`：是否正在打开某个更深入的详情界面。

可以把它们看成一张“当前界面地址卡”：

```text
App
├─ bottomTab     = home
├─ homeView      = scene
├─ homeSub       = everyday
└─ detailScreen  = null
```

这不是浏览器地址栏，也不是后端数据。它只是前端暂时保存的“我现在应该展示什么”。

这就是本项目的一个重要特点：它目前主要使用 React State 做页面切换，而不是依靠 URL 路由。项目里虽然有一些路由相关依赖，但当前这套主要界面没有用 `BrowserRouter`、`Routes`、`Route` 来组织页面。

## 3. `HomeTopTabs`：顶部导航栏只是一个“操作面板”

`HomeTopTabs` 是顶部的 Scene、Agents、Plaza、链上广场那一排按钮。

它从父组件 `App` 接收的主要 Props 是：

- 当前选中的 `scene`；
- 当前选中的 `view`；
- `onSceneChange`：Scene 改变时通知父组件；
- `onViewChange`：顶部栏目改变时通知父组件；
- `accent`：当前主题色。

这里先抓住一个关键概念：

> Props 是父组件交给子组件的输入；回调函数 Props 是子组件通知父组件“用户刚刚做了什么”的通道。

所以 `HomeTopTabs` 自己并不负责决定整个 App 要显示哪一个页面。它更像一个遥控器：用户点击后，它调用 `onViewChange(...)` 或 `onSceneChange(...)`，把操作报告给 `App`。

## 4. `navigate()`：项目自己的“页面跳转函数”

`App.tsx` 里的 `navigate(s)` 是一组页面跳转规则。

例如，某个世界卡片想进入 Vitality Gym，它不会打开一个新的浏览器地址，而是调用类似“进入 everydayTown”的导航动作。`navigate()` 接到这个动作后，会同时修改几项 State：

```text
进入 Vitality Gym
→ bottomTab 改成 home
→ homeView 改成 scene
→ homeSub 改成 everyday
→ detailScreen 清空
```

因此，`navigate()` 的本质不是“搬运页面文件”，而是“把当前界面状态改成另一组值”。

## 5. `renderSection()`：根据 State 决定显示谁

`renderSection()` 可以理解成一个交通指挥员。它读取 `App` 当前的 State，然后选择应该展示的 Screen。

它的大致判断顺序是：

1. 如果 `detailScreen` 有值，优先显示详情界面；
2. 否则看 `bottomTab`，决定是在 Home、Capture 还是 Inventory；
3. 如果当前是 Home，再看 `homeView`；
4. 如果当前是 Scene，继续看 `homeSub`；
5. 最后决定显示 `WorldDockScreen`，还是某个具体世界的 `ThemedWorldHostScreen`。

可以把它简化成：

```text
当前 State
    ↓
renderSection()
    ↓
符合条件的 Screen 组件
    ↓
浏览器里的新界面
```

当 State 改变时，React 会重新计算这部分界面，并更新真正发生变化的地方。不是浏览器重新加载整个网站，也不是把所有文件重新下载一遍。

## 6. 两个 Screen 组件分别是什么角色？

### `WorldDockScreen`

它是 Home 里的世界总览页，也就是你看到三个世界卡片的地方。

它接收的主要 Props 包括：

- `navigate`：点击世界卡片或 Capture 时请求页面切换；
- `sceneControl`：顶部导航栏；
- `onOpenChronicle`：打开 Agents 目录；
- `myAgents`：当前用户的 Agent 数据。

第一课只需要理解：它负责“展示世界入口”，并把用户的点击交给 `navigate`。

### `ThemedWorldHostScreen`

它是某一个具体世界的外壳，例如 Vitality Gym、Learning Commons 或 Maker Harbor。

它接收的主要 Props 包括：

- `worldKey`：当前是哪一个世界；
- `navigate`：继续进行页面跳转；
- `sceneControl`：顶部导航栏；
- `myAgents`：当前用户的 Agent；
- `onAgentsChanged`：Agent 发生变化后通知外层刷新。

它再根据 `worldKey` 找到这个世界的主题和居民，交给更具体的世界画面组件展示。具体的 Agent 数据处理先留到后面，不在第一课展开。

## 7. 走一遍真实路径：选择 Vitality Gym

你可以把刚才看到的页面操作翻译成下面这条链：

```text
你在顶部选择 Scene / Vitality Gym
        ↓
HomeTopTabs 接收到点击
        ↓
调用 onSceneChange 和 onViewChange
        ↓
App 修改 homeSub 和 homeView
        ↓
React 重新计算 App 的界面
        ↓
renderSection() 发现：homeView 是 scene，homeSub 是 everyday
        ↓
选择 ThemedWorldHostScreen
        ↓
浏览器显示 Vitality Gym
```

这条路径里暂时没有后端，也没有数据库。它只是“用户操作 → 前端状态 → 前端组件选择”。

## 8. 这一课暂时不要看的东西

- `src/app/components/ui/`：这是按钮、输入框等通用视觉零件，不是页面切换主线；
- `backendApi.ts`：它属于下一条“前端请求后端”的主线；
- 每一个 Agent 的状态、心情和数据库字段：这些属于页面显示数据，不影响我们先理解导航骨架；
- `App.tsx` 中所有其他 State：这个文件很大，不需要从头读到尾。

## 小结

- `main.tsx` 启动 React，并把 `App` 放进页面。
- `App` 保存当前界面的关键 State。
- `HomeTopTabs` 通过 Props 得到当前状态，并通过回调通知 `App` 用户点击了什么。
- `navigate()` 通过修改 State 实现项目内部的页面跳转。
- `renderSection()` 读取 State，决定最终显示哪个 Screen。

## 下一篇预告
