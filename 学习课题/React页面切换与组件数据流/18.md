# 18｜详情返回后去哪了：detail 如何让卡片显示内容

## 这一讲只解决一个问题

第 17 讲已经追踪到：

~~~text
用户点击 Agent 卡片
→ expandedId 保存 Agent 编号
→ backendApi.agent(expandedId)
→ 后端返回详情
~~~

这一讲只继续往后看：

~~~text
后端返回详情
→ detail 保存详情
→ 当前卡片显示 Skills 和记忆
~~~

本讲继续只看 AgentsDirectoryScreen，不看 Scene、Plaza 或 AgentProfileSheet。

## 第一步：detail 是什么

位置：

~~~text
frontends/mobile/src/app/App.tsx:5503
~~~

这里有一个前端变量：

~~~text
detail
~~~

它表示：

~~~text
当前被点击的 Agent 的详细资料。
~~~

刚进入页面时，还没有点击任何 Agent，所以：

~~~text
detail = 空
~~~

这里的 detail 是前端运行时的变量。它不是数据库文件，也不是数据库表，更不是一个页面。

当前这条路径中，真正负责显示页面的是 AgentsDirectoryScreen；detail 只是其中保存数据的一个变量。

## 第二步：后端返回结果后，放进 detail

位置：

~~~text
App.tsx:5513-5520
~~~

当 expandedId 等于 3 时，前端请求：

~~~text
backendApi.agent(3)
→ GET /api/agents/3
~~~

请求成功后，后端返回一份数据。代码里把这份返回数据暂时叫作 row，然后执行：

~~~text
setDetail(row)
~~~

可以直接理解成：

~~~text
把后端返回的 Agent 详情保存到 detail 里。
~~~

例如后端返回：

~~~json
{
  "id": 3,
  "name": "豆豆",
  "location": "plaza",
  "skills": [...],
  "memories": [...]
}
~~~

那么保存之后可以理解为：

~~~text
detail = 豆豆的这份完整详情
~~~

这里要区分两个东西：

~~~text
setDetail
→ 更新 detail 的函数

detail
→ 当前保存的详情数据
~~~

调用 setDetail 后，页面会使用新的 detail 重新显示内容。

## 第三步：expandedId 和 detail 各自负责什么

这两个变量容易混在一起，但它们负责的事情不同：

| 变量 | 它回答的问题 |
|---|---|
| expandedId | 哪一张卡片要展开？ |
| detail | 展开的卡片要显示哪些详细内容？ |

例如点击 id 为 3 的豆豆：

~~~text
expandedId = 3
detail = 豆豆的详细资料
~~~

因此：

~~~text
expandedId 决定显示位置
detail 决定显示内容
~~~

## 第四步：代码怎样判断当前卡片是否应该展开

位置：

~~~text
App.tsx:5538-5539
~~~

页面正在遍历每一只 Agent 时，会比较：

~~~text
expandedId === agent.id
~~~

假设现在正在生成豆豆这张卡片：

~~~text
expandedId = 3
agent.id = 3
~~~

两者相等，所以这张卡片被标记为 expanded。

其他卡片例如雪糕：

~~~text
expandedId = 3
agent.id = 4
~~~

两者不相等，所以雪糕卡片保持收起状态。

## 第五步：expanded 为真时，才显示额外内容

位置：

~~~text
App.tsx:5574-5600
~~~

这里的：

~~~text
expanded
~~~

可以理解成当前卡片是否被选中。

当 expanded 为真时，页面显示额外区域：

~~~text
显示 Skills
显示最近记忆
~~~

Skills 的数据来自：

~~~text
detail.skills
~~~

记忆的数据来自：

~~~text
detail.memories
~~~

所以最终显示内容的条件是：

~~~text
当前卡片是被选中的那一张
并且
detail 已经从后端返回
~~~

## “页面、组件、变量”在这里分别是什么

这一段代码里可以这样分开：

~~~text
AgentsDirectoryScreen
→ 当前整个 Agents 页面组件

detail
→ 这个组件内部保存详情的变量

expandedId
→ 这个组件内部保存选中编号的变量

Skills 和记忆的显示区域
→ AgentsDirectoryScreen 返回的页面内容的一部分
~~~

当前路径中没有跳转到另一个详情页面。卡片是在原来的 Agents 页面里直接展开的。

## 一条最短流程

~~~text
点击豆豆卡片
→ expandedId = 3
→ 请求 /api/agents/3
→ 返回豆豆详情
→ detail 保存豆豆详情
→ expandedId === 豆豆的 id
→ 豆豆卡片展开
→ 读取 detail.skills 和 detail.memories
~~~

## 点击同一张卡片第二次会发生什么

点击已经展开的豆豆卡片时：

~~~text
expandedId = 3
agent.id = 3
expanded = true
→ setExpandedId(null)
~~~

这表示取消选中：

~~~text
expandedId 变为空
→ detail 被清空
→ 没有卡片继续展开
~~~

所以这个按钮同时承担了两个动作：

~~~text
点击收起的卡片
→ 展开它

点击已经展开的卡片
→ 收起它
~~~

## 小结

- detail 是 AgentsDirectoryScreen 内保存详情的前端变量。
- 后端返回的 row 会通过 setDetail(row) 放进 detail。
- expandedId 决定哪张卡片被选中。
- detail 决定被选中的卡片显示哪些 Skills 和记忆。
- 当前实现把详情直接展开在原来的 Agent 卡片里，没有跳转到另一个页面。

这一条功能可以压缩成：

~~~text
expandedId 决定“哪张卡片展开”
detail 决定“展开后显示什么”
~~~
